# 第三方模型的输出额度：Opus 5.5 实测记录

本文记录一次 Codex 桌面端超长会话在第三方 Responses 路由上的排查。测试日期为 2026-10-22；结果只适用于当时测试的 `claude-opus-5-5` 路由，不保证其他服务商或以后版本相同。

## 现象与归因边界

该会话在约 34–35 万输入 token、`xhigh` 推理强度下，三笔请求的输出都恰好是 8192 token，Codex 报 `Incomplete response returned, reason: max_output_tokens`。失败前只有只读检查，没有执行写入规划 Markdown 文件的工具调用。按 [Responses 推理指南](https://developers.openai.com/api/docs/guides/reasoning)，`max_output_tokens` 包括推理过程和可见输出；推理用尽额度时，即使正文还没写完，也会得到不完整响应。它与模型目录中的 `context_window`、自动压缩阈值是不同的参数。

为了查清请求来源，用同版本 Codex CLI 向**本机临时接收端**发送了一个新会话的 `xhigh` 请求。接收端只读取模型、推理强度、流式标志和 `max_output_tokens` 是否存在，不转发提示词、凭据或请求到服务商。捕获结果是客户端**省略** `max_output_tokens`。此前适配器对普通对话也原样转发，没有补入该字段。这与第三方路由在未指定额度时表现出 8192 的有效默认值一致。原失败会话有活跃写入者，未能捕获它的原始请求体，所以不能断言服务商内部具体在哪一层使用了该默认值。

适配器的旧历史摘要路径另有一个显式 8192 上限，但摘要请求使用 `low`，与后台这三笔 `xhigh` 请求不同。调大历史摘要上限不能解决这次普通对话的报错。

## 可接受上界的低成本测试

用“只回答 OK”的 `xhigh` 短请求测试同一第三方路由，得到：

| 请求的 `max_output_tokens` | 结果 |
| ---: | --- |
| 65536 | HTTP 200，正常完成 |
| 128000 | HTTP 200，正常完成 |
| 128001 | HTTP 400，提示该模型最多允许 128000 |
| 131072 | HTTP 400，同一上限提示 |

因此这个**网关接受的请求参数上界是 128000**，而不是把“128K”换算成 131072。[Anthropic 的 Opus 5.5 规格](https://platform.claude.com/docs/en/models/opus-5-5/overview)也标称最大输出 128K。测试请求仅产生几个输出 token：HTTP 200 证明参数被接受，**没有证明**模型实际生成接近 128000 token 时一定能完成，网关也可能有其他运行时限制。

先把该路由缺省额度从省略改为 32768 后，用户反馈原会话已能写出规划 Markdown 文件；随后才按上述边界测试把本机缺省额度提高到 128000。前者是具体任务恢复的反馈，不能当作接近 128000 token 的长输出压力测试。

## 在补丁中设置

将额度放在私有 `connections.json` 的模型规格里；密钥只填环境变量名称：

```json
{
  "model_specs": {
    "claude-opus-5-5": {
      "context_window": 1000000,
      "default_max_output_tokens": 128000
    }
  }
}
```

上面只展示连接对象中的 `model_specs` 片段，不是完整连接文件。完整无密钥结构见 [示例连接文件](../examples/connections.example.json)。上下文长度也应以当前服务商提供的能力为准。构建器把 `default_max_output_tokens` 带入模型路由；适配器只在 Codex 请求**没有** `max_output_tokens` 时补入该值。如果客户端显式指定额度，仍按客户端的值转发。官方 GPT 路由不受影响；High、XHigh 等推理强度使用同一模型路由设置。

常规更新请用私有连接文件重新 `build --verify`，正常退出 Codex 后 `install` 新构建，再启动 Codex。只改运行目录中的 `adapter-profile.json` 会使构建清单的哈希校验失效，也可能被后续重建覆盖。适配器服务重启后，新请求就会使用新额度；旧的失败轮次不会自动续跑。

## 实际使用时的限制

`max_output_tokens` 是**单次请求的预算上限**，不是要求模型输出这么多。它不能设成无限；到达上限仍可能报不完整响应。把上限设为 128000 降低了因 8192 默认额度过早截断的风险，同时增加了失控推理或冗长生成时的潜在费用。长任务最好让模型尽早通过工具写入文件、分阶段完成，并在跨模型切换时提供简短可读交接；不要仅依赖一次最终长回复来保存工作。

本仓库不包含真实 API Key、私有服务地址、用户配置或计费记录。复核其他网关时，也应使用短请求分别测试边界值与边界值加一，并将“参数被接受”和“长输出确实完成”分开记录。
